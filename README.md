# 灰度发布台（grayroll）

**所属领域：应用开发 · 子方向：全栈开发**

全栈产品：功能开关登记 → 环境绑定 → 人群圈选 → 灰度规则 → 发布生效 → 紧急熔断 → 单点覆盖 → 变更历史 → 在线求值。

## 骨架一句话

功能开关按环境配置灰度比例与人群，发布须版本落库才能生效，紧急熔断与变更历史同源。

## H3 切口候选（写路径互斥 · 须择一）

1. **发布生效**：同事务写入正式生效配置并升版本锁旧版，或只写影子发布草案、升正时原子落正式区（正式区升正前零改）。
2. **紧急熔断**：同事务立即写正式关闭并记变更，或影子紧急草案确认后原子熔断。
3. **人群绑定**：同事务写正式人群规则，或影子绑定草案升正。

正确性口径只能走甲乙中的一种且两边不得混用。

## 爬坡步进正确性口径（grayroll-02 · 当班封死）

单步爬坡增量上限 20%。本切片择定**甲路径**，并封死如下：

- **甲（采用）**：超步时整笔拒写，正式规则册零增、游标不动、不落任何影子草案；合法步进在**同一事务**内写正式规则与发布册（同版本），并跨表联查账实后才提交。
- **乙（不采用）**：超步只落影子爬坡草案，拆成合法步进后再原子升正。本切片不得与甲混用，也不得新增第三路。
- 争用段（`backend/locks.py` 行锁/争用痕）与取舍段（`backend/step_policy.py` 步长口径）物理分开：同一开关上的爬坡互斥，未抢到锁的一方只产生争用记录（409），不得落正式。
- 对比矩阵不得把未升正草案当成已对齐：`has_pending_shadow` / `aligned` / `pending_percent` 显式暴露草案状态。
